- Svelte frontend uses runes mode; use `$derived`/`$effect` instead of legacy `$:` reactive statements in route components.
- **CRITICAL**: in runes mode a plain `let` is NOT reactive. URL-derived state (`fullText`, `isDoneFilter`, ...) must snapshot the URL as `let currentUrl = $state(page.url)` (see `src/routes/+page.svelte`, `discussions/+page.svelte`). A non-reactive `let currentUrl = page.url` makes `$derived(currentUrl.searchParams...)` compute once and never recompute after `afterNavigate` reassigns it — toggles silently stop reflecting the URL (regression found in `notices/+page.svelte`, fixed 2026-10-01). e2e tests that only assert the URL will not catch this; assert `aria-checked`/UI state too.
- **CRITICAL (repeat offender)**: `notices/[num]/+page.svelte` shipped the runes migration with `let currentUrl = page.url` (no `$state`), so every URL-derived `$derived` on that page (timeline compare selection `cmpFrom`/`cmpTo`, `?timeline`/`?archive`/`?rev` flags, back link) went stale after `goto` — the 변경 추적 타임라인 compare buttons updated the URL but the UI never reacted (fixed 2026-10-03, guarded by `e2e/notice-detail.spec.ts` "change timeline compare mode"). Assert UI state, not just the URL.
- **`$state` proxies objects — identity comparisons need `$state.raw`**: storing an object in `$state` wraps it in a reactive proxy, so `stored === originalPayload` is always false (Svelte 5). When state pins "which payload was acted on" (e.g. the semantic-search weak-results reveal in `routes/notices/semantic-search/+page.svelte`), declare it `$state.raw` or the comparison silently never matches — only an e2e click test catches it.
- Rate-limit overlays must tick `retryAfter` through `RetryCountdown` (setters writing `$state`); a static retryAfter freezes the "N초 후..." text and leaves the overlay's retry button disabled forever (semantic-search page bug, fixed 2026-10-03, guarded by `e2e/semantic-search.spec.ts` "rate-limit overlay counts down").
- **A route component may declare its own inline `data` prop type — adding a field in `+page.server.ts` is not enough.** `notices/+page.svelte` spells out `let { data }: { data: { archive: ...; digestContext?: ...; loadError?: ... } } = $props()`, so a new loader field (e.g. `exampleQueries`) fails `npm run check` with `Property 'X' does not exist on type '{ archive: ... }'` **pointing at the component, not the loader**. Extend that inline type in the same change; regenerating `.svelte-kit` will not help. (Hit 2026-10-13 adding `exampleQueries`.)
- **Removing a URL-parameter toggle is a multi-surface change; grep the parameter name, not the label.** Dropping the `/notices` toggle (`fullText`, label 원문 포함 검색) touched nine places in one route: the `$derived` state, `buildQueryLink` (+ a `params.delete('fullText')` so old links self-clean), the `buildFilterLink`/`buildPageLink` derived-argument tuples, the form's hidden input and `handleFilterSubmit`, the active-filter chip, the empty-state reset, the search placeholder, the loader, `client.ts`, the home page quick-search link/hidden input, the mock module, and five e2e specs (including a dismiss-chip test and a home-link assert). Also decide explicitly what happens to stale bookmarks: here the server ignores the parameter and the first client-side navigation drops it, verified by an e2e that loads `?fullText=true` and submits. Do the same scan for any flag you delete; a leftover reference shows up as a silent behavior difference, not a type error, when it is only passed as a query param.
- **A browser-issued API call has no mock seam unless the proxy route answers it.** `handleFetch` (`hooks.server.ts`) only intercepts SSR fetches; the `getMockResponse` helpers in `routes/api/[...path]/+server.ts` are what answers the browser. A new client-side read (e.g. the board's on-demand keyword count on `/api/notices/archive`) therefore 502s in `DIFFCHAIN_UI_MOCK=1` until a matching branch exists there — the feature looks broken in tests while production is fine. Add the branch in the same change and exercise it from a spec. (2026-10-13.)
- **Clicking a hydrated-only control right after `page.goto` is a silent no-op, so a single `click()` is a flaky test.** Svelte islands attach handlers after hydration; the board's mode/reveal/count controls need a retry that re-issues the click until its effect appears (`await expect(async () => { await click(); await expect(effect).toBeVisible({ timeout: 1000 }); }).toPass({ timeout: 20_000 })`). Plain anchors (example chips, mode links) navigate without JS and do not need this. Board coverage now lives in `e2e/semantic-search-board.spec.ts` (semantic config only — the flag decides if the controls exist at all).
- **Two identical sentences copied across surfaces drift; keep user-facing copy in one module.** `lib/utils/semantic-search.ts` owns the board's search-mode hints, relevance-chip tooltips and the weak-tier reveal/paging copy (`describeWeakReveal`, `describeWeakProgress`, `WEAK_RESULT_PAGE_SIZE`), and both `/notices` and `/notices/semantic-search` import it. (2026-10-13.)
- **HTML that embeds a per-request random draw needs an explicit `Cache-Control`; SvelteKit sends none for a dynamic page.** The example-query chips (`pickExampleQueries`, random per request) ride in the SSR payload of both `/notices` and `/notices/semantic-search`, so a shared cache — or a browser's heuristic freshness — could pin one visitor's three chips and replay them to everyone, reproducing the frozen-chips symptom that made a deterministic draw look attractive in the first place. Both loaders call `setHeaders({ 'cache-control': PER_REQUEST_HTML_CACHE_CONTROL })` from `lib/server/ssr-cache-policy.ts` (`private, no-cache`), pinned by header assertions in `e2e/semantic-search-board.spec.ts` and `e2e/semantic-search.spec.ts`. The `handle` hook minifies HTML by re-wrapping the resolved response with its own headers, so a directive set in a loader survives to the client (verified against a production build, not only `vite dev`). Any new route that renders such a draw must do the same: without the directive it looks right in dev and is only wrong once a cache sits in front of it. (2026-10-13.)
