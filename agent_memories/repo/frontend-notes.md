- Frontend lives in frontend/ and validates with `cd frontend && npm run check`.
- Svelte frontend uses runes mode; use `$derived`/`$effect` instead of legacy `$:` reactive statements in route components.
- **CRITICAL**: in runes mode a plain `let` is NOT reactive. URL-derived state (`fullText`, `isDoneFilter`, ...) must snapshot the URL as `let currentUrl = $state(page.url)` (see `src/routes/+page.svelte`, `discussions/+page.svelte`). A non-reactive `let currentUrl = page.url` makes `$derived(currentUrl.searchParams...)` compute once and never recompute after `afterNavigate` reassigns it — toggles silently stop reflecting the URL (regression found in `notices/+page.svelte`, fixed 2026-10-01). e2e tests that only assert the URL will not catch this; assert `aria-checked`/UI state too.
- **CRITICAL (repeat offender)**: `notices/[num]/+page.svelte` shipped the runes migration with `let currentUrl = page.url` (no `$state`), so every URL-derived `$derived` on that page (timeline compare selection `cmpFrom`/`cmpTo`, `?timeline`/`?archive`/`?rev` flags, back link) went stale after `goto` — the 변경 추적 타임라인 compare buttons updated the URL but the UI never reacted (fixed 2026-10-03, guarded by `e2e/notice-detail.spec.ts` "change timeline compare mode"). Assert UI state, not just the URL.
- **`$state` proxies objects — identity comparisons need `$state.raw`**: storing an object in `$state` wraps it in a reactive proxy, so `stored === originalPayload` is always false (Svelte 5). When state pins "which payload was acted on" (e.g. the semantic-search weak-results reveal in `routes/notices/semantic-search/+page.svelte`), declare it `$state.raw` or the comparison silently never matches — only an e2e click test catches it.
- Rate-limit overlays must tick `retryAfter` through `RetryCountdown` (setters writing `$state`); a static retryAfter freezes the "N초 후..." text and leaves the overlay's retry button disabled forever (semantic-search page bug, fixed 2026-10-03, guarded by `e2e/semantic-search.spec.ts` "rate-limit overlay counts down").
- Stable AI/test navigation benefits from semantic landmarks plus explicit `data-testid` hooks on primary regions and nav links.

- Large multi-hunk apply_patch edits in frontend/src/app.css can misapply; prefer restoring from frontend submodule HEAD and reapplying targeted patches, then run npm run check.

- Playwright e2e (`npx playwright test`, run from frontend/) proxies /notices, /proposals, etc. to the REAL backend unless DIFFCHAIN_UI_MOCK=1 is set (status/home/changes pages use lib/server/diffchain-ui-mock.ts under that flag). If the real backend isn't reachable, notices/proposals specs fail with ERR_CONNECTION_REFUSED/502 Bad Gateway — unrelated to unrelated frontend edits; rerun the specific specs to confirm before treating as a regression.
- **Trap**: the main Playwright config uses `reuseExistingServer` on port 5173 — if any dev server is already listening there (e.g. a plain `npm run dev` from a terminal) WITHOUT `DIFFCHAIN_UI_MOCK=1`, mock-fixture assertions fail against real data with confusing counts (e.g. `search=개인정보 보호법` returning 90). Before diagnosing "red tests", check what is on 5173 (`grep notice-detail-link-` on a rendered /notices page: mock nums are 22100xx) and run on a dedicated port/config instead of blaming the diff.
- notice-detail.spec.ts "invalid notice number shows error page" and notices.spec.ts "pagination is shown when there are results" are pre-existing data-dependent flaky failures (depend on live archive DB state), not caused by status-page/UI changes. The responsive spec fails/skips the same way (its `discoverFirstNotice` walks live archive data).
- **SSR data calls bypass the `/api/[...path]` proxy**: a `fetch('/api/...')` made inside `+page.server.ts` is answered by `handleFetch` (`src/hooks.server.ts`), which rewrites same-origin `/api/*` straight to `API_BASE_URL` — so browser-side `page.route('**/api/...')` stubs never see it, and so do the `getMockResponse` helpers in the proxy route. To stub an SSR-loaded endpoint for e2e, the hook must live in `handleFetch` (pattern: `lib/server/semantic-search-mock.ts`, gated by `DIFFCHAIN_UI_MOCK`). `handleFetch` is also where client-IP forwarding (`resolveClientIp(event.request)`) happens, which is why SSR calls keep their own rate-limit bucket.
- **SEO head tags have a single source of truth: `src/lib/components/SeoHead.svelte`.** Every route renders `<SeoHead title description url keywords [type]>`; the component owns the only `<title>` (template `페이지명 - LawCast` — it appends the brand suffix, so routes pass the page text WITHOUT ` - LawCast`), the canonical link and the description/keywords/og/twitter tags. Never hand-write those tags in a route `<svelte:head>`; page-specific extras (JSON-LD, `article:*` times, `robots noindex` on `+error.svelte`) stay in the route's own head block. Structure is guarded by `e2e/helpers/head-metadata.ts` (`expectHeadMetadata` requires exactly one copy of each tag). Added 2026-10-05 to unify the previously mixed title styles (`LawCast - X`, `X - LawCast`, `X | LawCast`).
- **Dynamic OG images for bills**: `/notices/[num]/og.png` (`src/routes/notices/[num]/og.png/+server.ts`) renders 1200x630 PNGs in `src/lib/server/og-image.ts`; the detail page passes `image` to `SeoHead`. **CRITICAL**: Cloudflare Workers forbids compiling WASM from bytes at runtime (`CompileError: Wasm code generation disallowed by embedder` works fine in Node dev, then 500s in production) — use `@cf-wasm/satori` + `@cf-wasm/resvg` (static ESM `.wasm` imports wrangler pre-compiles; their `node` export condition covers the Vite dev server), NOT `satori` + `@resvg/resvg-wasm`. Both yoga (satori) and resvg must be covered — the error names resvg while yoga may be the real blocker. Verified with `wrangler pages dev` (wrangler ships transitively via `@sveltejs/adapter-cloudflare`). The font (`static/og/fonts/Pretendard-Regular.otf`) is fetched same-origin since Workers has no filesystem; `static/og/README.md` documents provenance (font + `LICENSE.txt` OFL copy). **PITFALL**: satori only allows **array** `children` on `display:flex|contents|none` containers and throws `Expected <div> to have explicit "display: flex"...` otherwise — JSX semantics apply (single child = the value itself, no child = omit the key), so build element trees with a helper that normalizes children.
